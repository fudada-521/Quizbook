# 项目架构

> 状态：现行。编写于 2026-11-06。
> 本文描述项目的**整体架构**：分层、包边界、运行时、数据流、构建产物与不可违反的约束。
> 具体的后端与收费设计见 [`docs/后端与收费设计.md`](后端与收费设计.md)；题库格式与校验见该文档第五节。

---

## 一、一句话概括

一套 React 代码产出 **Web / 桌面 / 移动** 三端；一个 Fastify 服务提供**账号、题库、同步、会员**；一个独立后台供运营**维护题库与用户**；内置一套题库保证**离线永远可用**。

## 二、分层视图

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层                                                        │
│   apps/web（React）              apps/admin（React）           │
│   答题、收藏、成就、设置           题库编辑、发布、兑换码、用户   │
└───────────────┬──────────────────────────┬───────────────────┘
                │                          │
┌───────────────▼──────────────────────────▼───────────────────┐
│ 状态层                                                        │
│   apps/web/src/store/QuizStore.tsx   状态中枢（Context + Reducer）│
│   apps/web/src/store/sessionPersistence.ts  断点续做           │
└───────────────┬──────────────────────────┬───────────────────┘
                │                          │
┌───────────────▼──────────────────────────▼───────────────────┐
│ 领域层   packages/core                                        │
│   判分 / 抽题 / 错题 / 收藏 / 心得 / 挑战 / 成就 / 合并 / 校验   │
│   纯函数，无 DOM、无 localStorage、无网络                      │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│ 存储与传输层   packages/storage                               │
│   ProgressStore（localStorage）  BankRepository（IndexedDB）   │
│   CloudClient（HTTP）  auth（token/服务器地址）                │
└───────────────┬──────────────────────────────────────────────┘
                │ HTTP
┌───────────────▼──────────────────────────────────────────────┐
│ 服务端   apps/server（Fastify + node:sqlite）                  │
│   认证 / 题库发布 / 按题库同步 / 会员 / 兑换码 / 统计           │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│ 平台壳   apps/desktop（Tauri 2）   apps/mobile（Capacitor 7）   │
│   只提供窗口/原生能力，业务代码 100% 复用 apps/web 产物          │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向必须单向**：`apps/* → packages/storage → packages/core`。`core` 不依赖任何其他包，也不依赖运行环境；`server` 可以依赖 `core`，但不能依赖 `web`。

## 三、包职责

| 包 | 职责 | 依赖 | 产物 |
|---|---|---|---|
| `@megrez/core` | 平台无关的领域逻辑：`Question`/`QuizData`/`PersistedState`、`gradeAnswer`、抽题、错题、收藏、心得、挑战、成就、`mergeStates`、`validateBank` | 无 | 直接暴露 `src/*.ts`，无编译 |
| `@megrez/storage` | 持久化与传输：`ProgressStore`、`BankRepository`、`CloudClient`、token/服务器地址存储、导入导出 | `core` | 直接暴露 `src/*.ts` |
| `@megrez/web` | React UI 与状态管理；所有端的业务界面 | `core`、`storage` | `dist/index.html`（单文件） |
| `@megrez/admin` | 运营后台：题库编辑/发布、批量导入、兑换码、用户、统计 | `core`、`storage` | `dist/`（普通 SPA） |
| `@megrez/server` | Fastify API；生产环境同时托管 web 与 admin 静态产物 | `core`、`storage`（可选） | 无编译，`tsx` 直接运行 |
| `@megrez/desktop` | Tauri 壳，`frontendDist` 指向 `apps/web/dist` | — | `.app` / `.exe` / 二进制 |
| `@megrez/mobile` | Capacitor 壳，`webDir` 指向 `apps/web/dist` | — | `.ipa` / `.apk` |

约定：所有 workspace 包通过 `package.json` 的 `main`/`exports` 直接指向 TS 源码，**不要为它们增加 `dist` 构建步骤**。

## 四、运行时视图

### 4.1 纯本地（未登录 / 免费 / 断网）

```
apps/web ──读取──▶ 内置题库（构建期打进 bundle）
         ──读写──▶ localStorage：进度、会话、设置
         ──读写──▶ IndexedDB：已下载的其他题库（可选）
```

- 不产生任何网络请求。
- 内置题库 `id = builtin`，永久免费、可删除其他题库但不可删除它。
- 这是「双击 `index.html` 离线刷题」的形态。

### 4.2 连服务器（登录 / 会员）

```
apps/web ──登录──▶ /api/auth/*
         ──目录──▶ /api/banks
         ──下载──▶ /api/banks/:id/bundle   （会员）
         ──同步──▶ /api/banks/:id/sync     （会员）
         ──会员──▶ /api/membership、/redeem
```

- 题库包下载后落 IndexedDB，之后离线可用。
- 同步只针对当前题库；每个题库一份独立快照。
- 会员到期后，已下载题库继续可用，同步与下载停止。

### 4.3 部署拓扑（自建）

```
Internet
   │ 443
┌──▼────────┐
│  Caddy    │  TLS、gzip/zstd，全部反代
└──┬────────┘
   │ 8787
┌──▼─────────────────────────────┐
│ server 容器（Node 24）           │
│  /api/*        → Fastify 路由    │
│  /admin/*      → admin/dist      │
│  /*            → web/dist        │
│  /data/megrez.db → SQLite 卷     │
└────────────────────────────────┘
```

- 单镜像、单进程；见设计文档 10.3。
- 数据全部落在 `megrez-data` 卷，升级镜像不丢数据。

## 五、数据分类与生命周期

| 数据 | 来源 | 存储位置 | 是否跨端同步 | 收费门槛 |
|---|---|---|---|---|
| 内置题库 | `data/questions.json` → 构建期 | web bundle | 否（随版本更新） | 免费 |
| 其他题库包 | 服务端已发布版本 | 客户端 IndexedDB（回退 localStorage） | 否，按设备下载 | 会员下载 |
| 进度快照 | 答题产生 | `megrez_quiz_v1:<bankId>` + 服务端 `(user, bank)` | 是 | 会员 |
| 会话快照 | 断点续做 | `megrez_quiz_sessions_v2:<bankId>` | 否（设备级） | 免费 |
| 题库目录 | `GET /api/banks` | `megrez_bank_catalog_v1` | — | 公开 |
| 当前题库 | 用户切换 | `megrez_bank_current_v1` | 否（设备级） | — |
| 会员状态 | 服务端 | `megrez_membership_v1` 缓存 | — | — |
| 兑换码 | 后台生成 | 服务端 `redeem_codes` | — | — |
| 设置（音效/主题等） | 用户 | 进度快照内 / 本机主题键 | 设置随进度同步，主题不同步 | 免费 |

要点：

- **题库包**只读、可替换；**进度**可写、需合并；**会话**是设备级临时态。
- 主题、音效等本机偏好不参与多端合并。

## 六、核心数据流

### 6.1 答题判定

```
用户点选项
  → QuizView 调用 QuizStore.answer()
  → core.gradeAnswer(state, item, pick)
       ├─ 原地修改 PersistedState（answers/wrong/daily）
       └─ 原地修改 SessionItem（done/lastPick/fresh）
  → QuizStore 用 persistRef 取最新值 → setPersisted({...}) 触发重渲染
  → 判分结果决定是否自动跳转（shouldAutoAdvance）
```

约定：`core` 的函数**原地修改**对象，React 侧负责生成新引用。这是项目既有的「可变 core + 不可变 React 快照」约定，不能改成纯函数式。

### 6.2 题库下载

```
BankStoreView 点下载
  → 本地会员判断 → 必要时 GET /api/membership
  → GET /api/banks/:id/bundle
  → core.validateBank()
  → BankRepository.put()
  → 写入题库目录与版本
  → 若当前题库正是它，提示重进生效
```

### 6.3 进度同步

```
触发（登录后 / 切换题库 / 手动 / 空闲节流）
  → 取当前 bankId 的本地快照
  → PUT /api/banks/:id/sync
  → 服务端 mergeStates(客户端快照, 服务端快照)
  → 返回合并结果 → 客户端整体替换本地快照
```

`mergeStates` 是唯一合并实现，客户端与服务端共用。删除收藏靠 `favoriteRemovals` 墓碑，清空记录靠 `resetAt`/`dataResetAt` 纪元。

### 6.4 会员开通

```
用户在设置页输入兑换码
  → POST /api/membership/redeem
  → 服务端校验：存在、未使用、未作废
  → member_until = max(now, member_until) + duration
  → 写 membership_logs
  → 返回 { active, expiresAt }
  → 客户端更新 megrez_membership_v1
```

新注册用户由 `POST /api/auth/register` 直接写入 7 天试用。

## 七、构建与产物

| 命令 | 产物 | 说明 |
|---|---|---|
| `pnpm dev` | Vite 开发服务器 | Web 热更新 |
| `pnpm build` | `apps/web/dist/index.html` | 单文件、内联 JS/CSS，约 1.5 MB+ |
| `pnpm admin:build` | `apps/admin/dist/` | 普通多文件 SPA |
| `pnpm desktop:build` | Tauri 安装包 | 先构建 web |
| `pnpm mobile:sync` | Capacitor 同步 | 先构建 web |
| `pnpm server:dev` | 本地 API | 默认 `127.0.0.1:8787` |
| `docker compose ... up -d --build` | 单镜像 + Caddy | 含 web/admin/api |

单文件产物的意义：双击即可离线打开；PWA 可安装到主屏。任何需要额外静态资源加载的改动都会破坏这一点。

## 八、不可违反的约束

1. **`core` 保持纯粹**：不放 DOM、存储、网络、框架代码。
2. **workspace 包不产出 `dist`**：Vite / tsx / tsconfig paths 直接消费 TS 源码。
3. **题库的唯一来源是服务端发布包**：内置题库只是构建期快照；不要手工改客户端缓存的题库。
4. **进度按题库隔离**：任何读写进度的代码都必须知道当前 `bankId`。
5. **`mergeStates` 唯一实现**：客户端与服务端不得各写一套合并规则。
6. **题目标识用稳定 `questionId`**：`qkey()` 返回 `q.id`，不要再依赖 `${c}-${n}` 的稳定性。
7. **Web 构建保持单文件**：不引入运行时外部资源。
8. **视觉令牌集中在 `tokens.css`**：新界面复用 `.view-page` / `.view-head` 骨架，不另起配色。
9. **管理接口服务端鉴权**：前端隐藏只是体验优化，不是安全边界。
10. **收费只卡下载与同步**：刷题、本地进度、收藏、心得永远不联网、永远免费。

## 九、与旧架构的差异

| 维度 | 旧 | 新 |
|---|---|---|
| 题库 | 构建期唯一一份，`import` 进 bundle | 内置一份 + 服务端发布包，客户端按需下载 |
| 题目标识 | `${c}-${n}`，依赖题号稳定 | 稳定 `questionId`，题号仅展示 |
| 进度 | 所有题库共用一份 `PersistedState` | 每个「用户 × 题库」一份 |
| 同步 | `/api/sync` 全局一份 | `/api/banks/:id/sync` 按题库 |
| 账号 | 注册登录，同步免费 | 注册登录，同步与题库下载属于会员 |
| 后台 | 无（或内置在 Web 里） | 独立 `apps/admin` |
| 题库维护 | 直接改 `data/questions.json` 重新构建 | 后台编辑 → 草稿 → 发布不可变版本包 |
| 收费 | 无 | 订阅制 + 兑换码 + 7 天试用 |
| 部署 | 单镜像 + Caddy | 形态不变，镜像内增加 admin 产物 |
