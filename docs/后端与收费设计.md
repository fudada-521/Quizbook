## 一、目标与范围

### 1.1 要解决的问题

1. 内置一套清晖题库，**永久免费、无需登录、断网可用**。
2. 题库由服务端统一维护，客户端可浏览、下载、更新、切换多个题库。
3. 进度、错题、收藏、心得、成就**按题库完全独立**，互不污染。
4. 多端同步与「下载内置之外的题库」是**订阅会员**能力。
5. 会员可通过**兑换码**开通，暂不接在线支付。
6. 用独立管理后台维护题库、用户、兑换码与统计数据。

### 1.2 三层解耦（核心原则）

```
题库包        本地进度              云同步
免费内置       永远免费、永远本地      付费能力
付费下载       离线优先              在线时合并
```

收费只卡两个动作：**下载题库包** 与 **同步进度**。因此断网、未登录、会员过期，都不影响继续刷题。

### 1.3 非目标

- 本期不做题库文件的手动导入（不接文件选择器）。
- 本期不做多选、双空题；题库格式预留 `t` 字段，题型改造单独立项。
- 本期不接在线支付（微信/支付宝/App Store IAP），先做兑换码。
- 本期不做设备级并发限制、题库加密、DRM。

## 二、已确认决策

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 题库维护 | 独立管理后台（`apps/admin`） |
| 2 | 离线 | 登录可选，内置题库兜底；未登录全功能刷内置题库 |

| 7 | 后台能力 | 题库编辑、批量导入导出、草稿/发布、用户管理、兑换码、统计看板 |
| 8 | 题库更新 | 启动时比对版本，提示后由用户手动下载 |
| 9 | 后台形态 | 独立 `apps/admin`，与 Web 应用分开构建 |
| 10 | 收费形态 | 订阅制 |

| 14 | 试用 | 新注册送 7 天会员 |
| 15 | 进度存储 | 每个「用户 × 题库」一份独立 `PersistedState` 快照 |

## 三、系统架构

```
构建期
  data/questions.json ──import──▶ apps/web（内置题库 builtin，随包发布）

运行时
  apps/web ─┐
  desktop   ├── HTTP ──▶ apps/server（Fastify + SQLite）
  mobile    ┘                │
  apps/admin ─── HTTP ───────┘
```

- `apps/web` 是三端共用产物；`desktop` 与 `mobile` 只是壳，不单独接后端。
- 内置题库不落 IndexedDB，始终由构建产物直接提供。
- 下载的题库以完整包形式缓存在客户端（IndexedDB，失败回退 localStorage）。
- 服务端不记录「某用户下载了哪些题库」，下载状态属于设备级。
- 同步与题库下载都按 `bankId` 寻址，服务端不维护跨题库的合并状态。

## 四、服务端数据模型

数据库仍为 Node 24 内置 `node:sqlite`（`apps/server/src/db.ts`），不引入迁移框架，沿用 `PRAGMA table_info` 判断后迁移。

### 4.1 用户与认证

```sql
-- 现有表新增列
ALTER TABLE users ADD COLUMN role TEXT NOT NULL DEFAULT 'user';        -- user | admin
ALTER TABLE users ADD COLUMN member_until INTEGER NOT NULL DEFAULT 0;  -- 会员到期时间（毫秒）
ALTER TABLE users ADD COLUMN disabled_at INTEGER;                      -- 禁用时间，非空即禁止登录
```

- 会员判定：`member_until > Date.now()`，不单独建会员表。
- 续费在原到期时间上累加；已过期则从当前时间起算。

### 4.2 题库（草稿态）

```sql
CREATE TABLE IF NOT EXISTS banks (
  id              TEXT PRIMARY KEY,           -- [a-z0-9-]+，稳定不可变
  name            TEXT NOT NULL,
  subtitle        TEXT NOT NULL DEFAULT '',
  description     TEXT NOT NULL DEFAULT '',
  status          TEXT NOT NULL DEFAULT 'draft',  -- draft | published | archived
  current_version INTEGER NOT NULL DEFAULT 0,     -- 最近一次发布的版本号，0 表示从未发布
  question_count  INTEGER NOT NULL DEFAULT 0,
  chapter_count   INTEGER NOT NULL DEFAULT 0,
  created_by      TEXT REFERENCES users(id) ON DELETE SET NULL,
  created_at      INTEGER NOT NULL,
  updated_at      INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS bank_chapters (
  bank_id TEXT NOT NULL REFERENCES banks(id) ON DELETE CASCADE,
  c       INTEGER NOT NULL,
  title   TEXT NOT NULL,
  sort    INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (bank_id, c)
);

CREATE TABLE IF NOT EXISTS bank_questions (
  id          TEXT PRIMARY KEY,               -- 稳定题目 ID，题库内唯一且永不变
  bank_id     TEXT NOT NULL REFERENCES banks(id) ON DELETE CASCADE,
  c           INTEGER NOT NULL,
  n           INTEGER NOT NULL,
  stem        TEXT NOT NULL,
  options     TEXT NOT NULL,                  -- JSON string[]，本期固定 4 项
  answer      INTEGER NOT NULL,               -- 0 基下标
  explanation TEXT NOT NULL DEFAULT '',
  source_tag  TEXT NOT NULL DEFAULT '',
  updated_at  INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_bank_questions_bank ON bank_questions(bank_id, c, n);
```

### 4.3 已发布版本（不可变）

```sql
CREATE TABLE IF NOT EXISTS bank_releases (
  bank_id      TEXT NOT NULL REFERENCES banks(id) ON DELETE CASCADE,
  version      INTEGER NOT NULL,
  bundle       TEXT NOT NULL,                 -- 完整题库包 JSON，客户端直接消费
  note         TEXT NOT NULL DEFAULT '',
  published_by TEXT REFERENCES users(id) ON DELETE SET NULL,
  published_at INTEGER NOT NULL,
  PRIMARY KEY (bank_id, version)
);
```

**发布语义**：编辑只改动 `bank_questions` / `bank_chapters`。点「发布」时把当前草稿序列化成完整 bundle 写入 `bank_releases`，`current_version + 1`。客户端永远只读已发布包，因此：

- 不需要增量同步；
- 编辑到一半的内容不会被用户看到；
- 任意历史版本可回滚、可下载。

### 4.4 按题库的进度

现有 `user_states` 主键为 `user_id`，需要迁移为 `(user_id, bank_id)`：

```sql
CREATE TABLE IF NOT EXISTS user_states_v2 (
  user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  bank_id    TEXT NOT NULL REFERENCES banks(id) ON DELETE CASCADE,
  state      TEXT NOT NULL,
  version    INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (user_id, bank_id)
);

-- 迁移：旧 user_states 的每一行写入 (user_id, 'builtin')，随后 DROP 旧表并改名
```

成就表按题库重建：

```sql
CREATE TABLE IF NOT EXISTS user_achievements_v2 (
  user_id        TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  bank_id        TEXT NOT NULL REFERENCES banks(id) ON DELETE CASCADE,
  achievement_id TEXT NOT NULL,
  unlocked_at    INTEGER NOT NULL,
  PRIMARY KEY (user_id, bank_id, achievement_id)
);
```

### 4.5 会员与兑换码

```sql
CREATE TABLE IF NOT EXISTS redeem_codes (
  code          TEXT PRIMARY KEY,             -- MGR-XXXX-XXXX-XXXX
  batch_id      TEXT,                         -- 批量生成时的批次
  duration_days INTEGER NOT NULL,
  note          TEXT NOT NULL DEFAULT '',
  created_by    TEXT REFERENCES users(id) ON DELETE SET NULL,
  created_at    INTEGER NOT NULL,
  redeemed_by   TEXT REFERENCES users(id) ON DELETE SET NULL,
  redeemed_at   INTEGER,
  revoked_at    INTEGER
);

CREATE INDEX IF NOT EXISTS idx_redeem_codes_batch ON redeem_codes(batch_id);

CREATE TABLE IF NOT EXISTS membership_logs (
  id          TEXT PRIMARY KEY,
  user_id     TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  action      TEXT NOT NULL,                  -- trial | redeem | manual | revoke
  days        INTEGER NOT NULL,
  code        TEXT,
  operator_id TEXT,
  created_at  INTEGER NOT NULL
);
```

### 4.6 统计

```sql
CREATE TABLE IF NOT EXISTS activity_daily (
  date         TEXT NOT NULL,                 -- YYYY-MM-DD（服务端时区）
  bank_id      TEXT NOT NULL,
  active_users INTEGER NOT NULL DEFAULT 0,
  downloads    INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (date, bank_id)
);
```

数据来源（不新增客户端埋点）：

- `active_users`：登录、同步、下载时按 `(date, bank_id)` upsert 去重计数；
- `downloads`：每次成功返回题库包 +1；
- 答题量：由后台定时扫描 `user_states` 的 `daily` 字段汇总，用户量小时可接受。

## 五、题库文件规范

### 5.1 格式

```jsonc
{
  "schema": 1,                    // 题库文件格式版本，与进度 schemaVersion 无关
  "id": "qinghui-online",         // 题库 ID，稳定不可变
  "name": "清晖在线题库",
  "subtitle": "分章练习 + 全程班",
  "version": 3,                   // 整数，服务端发布时递增
  "chapters": { "1": "信息化发展", "25": "课后练习·信息化发展" },
  "questions": [
    {
      "id": "1-1",                // 稳定题目 ID，题库内唯一且永不变
      "c": 1,                     // 章节号，仅用于展示与排序
      "n": 1,                     // 章内题号，仅用于展示与排序
      "s": "题干",
      "o": ["A项", "B项", "C项", "D项"],
      "a": 3,                     // 0 基下标
      "e": "解析",
      "src": "分章练习"            // 可选，来源标签
    }
  ]
}
```

### 5.2 硬性规则

| 规则 | 说明 |
| --- | --- |
| 题库 `id` 不可变 | 改名等于换新题库，所有进度失联 |
| 题库 `id` 格式 | `[a-z0-9-]+`，不含冒号与空格 |
| 题目 `id` 不可变 | 它才是进度键；改题号不影响历史记录 |
| 题目 `id` 唯一 | 同一题库内必须唯一 |
| 题目 `id` 缺省 | 导入时用 `${c}-${n}` 生成 —— 内置题库刻意如此，以兼容旧进度 |
| `c` / `n` | 仅展示与排序，可以任意重排，后台移动题目不丢记录 |
| `o` 固定 4 项 | 本期不变；判断题预留 `t: "judge"`，后续单独立项 |
| `a` | 0 基整数，必须 `< o.length` |
| `e` | 允许为空 |
| 纯文本 | `s` / `o` / `e` 不放 HTML |

### 5.3 校验

新增 `packages/core/src/validate.ts`：

```ts
export interface BankValidation {
  ok: boolean;
  errors: string[];
  warnings: string[];
  removed: number;          // 被剔除的题数
}

export function validateBank(input: unknown): BankValidation;
```

检查项：

1. `schema` / `id` / `name` / `version` 齐备；
2. `id` 匹配 `^[a-z0-9-]+$`；
3. `questions` 非空；题目 `id` 唯一（缺省时先补 `${c}-${n}` 再判重）；
4. `c` 在 `chapters` 中有标题；
5. `o` 为长度 4 的字符串数组；`a` 为合法下标；
6. 题干非空；
7. 内置题库在构建期与单测里同样跑一遍。

导入命令与后台导入都调用同一实现，不允许服务端另写一套。

## 六、进度模型

### 6.1 一份快照 = 一个「用户 × 题库」

`PersistedState` 结构**不变**，`SCHEMA_VERSION` 保持 `6`。题库维度放在存储层，而不是塞进状态里：

- 客户端：每个题库一个 localStorage 键；
- 服务端：`user_states_v2` 主键 `(user_id, bank_id)`；
- `mergeStates(a, b)` 的语义不变，只是每次只在同一题库的两份快照之间调用。

这样做的好处：不需要给题目键加前缀，不需要 `bankResets` 墓碑，删除题库就是删除整份快照。

### 6.2 题目标识

`packages/core/src/types.ts`：

```ts
export interface Question {
  id: string;          // 稳定题目 ID，新增
  c: number;
  n: number;
  s: string;
  o: [string, string, string, string];
  a: number;
  e: string;
}

export function qkey(q: Pick<Question, 'id' | 'c' | 'n'>): string {
  return q.id ?? `${q.c}-${q.n}`;
}
```

- 内置题库的每道题在构建时补 `id = `${c}-${n}``，因此现有 localStorage 里的 `answers`/`favorites`/`notes`/会话快照**键完全不变，零迁移**。
- 新题库导入时生成 UUID，后台随意改章节与题号都不会让记录错位。
- 所有接收 `Pick<Question, 'c' | 'n'>` 的地方改为 `Pick<Question, 'id' | 'c' | 'n'>`：`qkey`、`isFavorite`、`toggleFavorite`、`notesFor`、`addQuestionNote`。
- `QuizData` 增加 `id: string`、`name: string`、`version: number`、`subtitle?: string`。

### 6.3 客户端存储键

| 键 | 内容 |
| --- | --- |
| `megrez_quiz_v1:<bankId>` | 该题库的 `PersistedState` |
| `megrez_quiz_sessions_v2:<bankId>` | 该题库的断点续做快照表 |
| `megrez_bank_current_v1` | 当前选中的题库 ID，默认 `builtin` |
| `megrez_bank_catalog_v1` | 服务端题库目录的缓存（元数据） |
| `megrez_membership_v1` | `{ active, expiresAt, checkedAt }` |

IndexedDB：

- 数据库 `megrez_banks`，对象仓库 `banks`，`keyPath: 'id'`；
- 值：`{ id, name, subtitle, version, questionCount, chapterCount, installedAt, data }`；
- 内置题库不写入。

### 6.4 迁移

1. 首次启动读取 `megrez_quiz_v1`，复制到 `megrez_quiz_v1:builtin`；旧键保留不删（只读），并写入标记 `megrez_migrated_v7`，避免重复复制。
2. `megrez_quiz_sessions_v2` 整体复制到 `megrez_quiz_sessions_v2:builtin`。
3. 无 `bank` 字段的旧会话视为 `builtin`，结构不变。
4. 服务端迁移：旧 `user_states` 的每行落到 `(user_id, 'builtin')`。

### 6.5 成就、挑战与每日统计

三类数据全部按题库独立：

- 成就：`applyAchievements(state, quizData)` 天然只作用于当前题库的状态与题库数据；
- 挑战：`challenges` 存在该题库快照里；
- `daily`（答题数、打卡、连续天数）：存在该题库快照里。

> 与归档文档的「daily 全局」不同，这里按本次决策改为按题库独立。理解为「每个题库有自己的学习进度」。

### 6.6 切换题库

```
switchBank(next):
  1. next === current                  → 无操作
  2. 正在答题                          → 保存当前会话快照
  3. 加载 next 的题库数据              → builtin 用包内数据；其余读 IndexedDB
  4. 加载 megrez_quiz_v1:<next>        → 不存在则 normalizeState({})
  5. 加载 megrez_quiz_sessions_v2:<next>
  6. 用新题库重新评估成就与首页统计
  7. 写 megrez_bank_current_v1
  8. 回到首页
```

切换是纯本地操作，不需要联网。

### 6.7 删除题库

- 内置题库不可删除。
- 只删除本地：题库包 + `megrez_quiz_v1:<bankId>` + `megrez_quiz_sessions_v2:<bankId>`。
- 云端进度**默认保留**：重新下载同 ID 题库后，会员再次同步即可恢复。
- 若用户勾选「同时删除云端记录」，调用 `DELETE /api/banks/:id/sync`（仅会员，可选实现）。

## 七、API 设计

### 7.1 权限分层

| 层 | 条件 |
| --- | --- |
| 公开 | 无需 token |
| 登录 | 有效 Bearer token 且用户未禁用 |
| 会员 | 登录 且 `member_until > now` |
| 管理员 | 登录 且 `role = 'admin'` |

新增中间件 `requireMember`、`requireAdmin`，与现有 `requireUser` 同一实现风格。

### 7.2 公开 / 登录

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | 公开 | 健康检查 |
| GET | `/api/config` | 公开 | `{ registerEnabled, publicUrl }` |
| POST | `/api/auth/register` | 公开 | 注册；首个用户 `role=admin`；所有新用户 `member_until = now + 7d` 并记 `trial` |
| POST | `/api/auth/login` | 公开 | 登录；禁用用户返回 403 |
| POST | `/api/auth/logout` | 登录 | 吊销当前 token |
| GET | `/api/me` | 登录 | `{ user, membership: { active, expiresAt } }` |
| GET | `/api/banks` | 公开 | 已发布题库元数据列表（不含题目） |
| GET | `/api/membership` | 登录 | `{ active, expiresAt }` |
| POST | `/api/membership/redeem` | 登录 | `{ code }` → 续期后的 `{ active, expiresAt }` |

`GET /api/banks` 响应：

```json
[
  {
    "id": "builtin",
    "name": "软考高项 · 综合知识",
    "subtitle": "分章练习 + 课后练习",
    "version": 3,
    "questionCount": 2726,
    "chapterCount": 68,
    "updatedAt": 1762387200000
  }
]
```

### 7.3 题库内容与同步（会员）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/banks/:id/bundle?version=N` | 返回完整题库包；支持 `ETag`、`If-None-Match`、`304`、gzip。`builtin` 允许公开访问 |
| GET | `/api/banks/:id/sync` | 该题库的云端进度 `{ state, version, updatedAt }` |
| PUT | `/api/banks/:id/sync` | 上传并合并，`bodyLimit: 20MB` |
| DELETE | `/api/banks/:id/sync` | 可选：删除该题库的云端进度 |

`PUT /api/banks/:id/sync` 行为与现有 `/api/sync` 一致，只是多一个 `bank_id` 维度：

1. 校验 `state` 形状；
2. 取当前 `(user, bank)` 快照；
3. `mergeStates(normalizeState(state), current.state)`；
4. 若题库包存在，用该题库的 `applyAchievements` 复核成就；
5. 版本冲突返回 `409` 与最新快照。

### 7.4 管理接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/banks` | 全部题库（含草稿、归档） |
| POST | `/api/admin/banks` | 新建题库 |
| PATCH | `/api/admin/banks/:id` | 改名、简介、状态 |
| DELETE | `/api/admin/banks/:id` | 删除题库及发布包（已下载用户保留本地副本） |

| `apps/web/src/views/SettingsView.tsx` | 增加「题库」与「账号/会员」区块 |

### 8.2 启动流程

1. 用包内 `data/questions.json` 构造内置题库（补 `id`、`name`、`version`）。
2. 读取 `megrez_bank_current_v1`，默认 `builtin`。
3. 若当前不是内置题库：从 IndexedDB 读取；读不到则回退 `builtin` 并清空当前选择。
4. 读取该题库的进度与会话快照，渲染界面。**这一步不联网。**
5. 若已登录：后台静默拉取 `/api/banks` 更新目录；会员且发现更高 `version` 时，在题库页标记「可更新」，**不自动下载**。

### 8.3 题库加载与缓存

```ts
export interface BankRepository {
  list(): Promise<InstalledBank[]>;
  get(id: string): Promise<QuizData | null>;
  put(bank: QuizData): Promise<void>;
  remove(id: string): Promise<void>;
}
```

- IndexedDB 可用时走 IndexedDB；不可用（部分 `file://` 场景）回退到 localStorage 键 `megrez_bank_cache_v1:<bankId>`。
- 回退模式下只允许缓存 **1 个**非内置题库，超出时提示用户先删除。
- 缓存不设 LRU 淘汰，由用户显式删除；下载前显示剩余空间提示。

### 8.4 下载与更新

```
downloadBank(bankId):
  1. 未登录            → 引导登录
  2. 本地会员已过期     → 刷新 /api/membership，仍过期则引导兑换
  3. GET /api/banks/:id/bundle
  4. 校验包结构与 id/version
  5. 写入 BankRepository
  6. 若当前题库正是它，提示「重新进入后生效」
```

更新 = 用新包覆盖同 ID 题库，进度保留。包内 `version` 变化但题目 ID 不变，因此历史记录仍然有效。

### 8.5 同步

- 只对**当前题库**发起同步，不做全量跨题库同步。
- 触发时机：登录后、切换题库后、设置页手动点「立即同步」、答题页空闲节流同步（沿用现有客户端策略）。
- 非会员：同步入口置灰，文案「多端同步为会员功能」。
- 免费用户升级会员后**第一次同步**：本地进度是 `base`，服务端已有记录参与 `mergeStates`，两端数据都会保留。

### 8.6 会员状态

```ts
interface CachedMembership {
  active: boolean;
  expiresAt: number;
  checkedAt: number;
}
```

- 存 `megrez_membership_v1`。
- **不在启动时校验**，避免破坏离线体验。
- 只在「下载题库」与「同步」前检查：若本地判断已过期，先请求 `/api/membership` 刷新一次。
- 服务端返回 401/403 时清除缓存并提示重新登录或续费。

### 8.7 UI 入口

| 位置 | 内容 |
| --- | --- |
| 首页 | 题库胶囊：当前题库名 + 切换入口 |
| 侧边栏 | 「题库」入口 |
| 设置页 · 题库 | 当前题库、题量、版本、更新、删除、进入题库商店 |
| 设置页 · 账号 | 登录/注册、会员到期时间、输入兑换码、同步开关 |
| `BankStoreView` | 题库列表：名称、副标题、题量、章节数、版本、状态（已安装/可更新/需会员/下载中） |
| 未登录浏览 | 可看列表，点下载时弹登录 |
| 免费用户点下载 | 弹「开通会员」与兑换码入口 |

视觉沿用 `.view-page` / `.view-head` 骨架与 `tokens.css`，不引入组件库。

## 九、会员与兑换码

### 9.1 权益

| 能力 | 未登录 | 免费登录 | 会员 |
| --- | --- | --- | --- |
| 内置题库刷题/进度/收藏/心得/成就 | ✅ | ✅ | ✅ |
| 浏览题库目录 | ✅ | ✅ | ✅ |
| 下载/更新其他题库 | ❌ | ❌ | ✅ |
| 多端同步 | ❌ | ❌ | ✅ |
| 会员到期后使用已下载题库 | — | — | ✅ |
| 管理后台 | ❌ | ❌ | admin |

### 9.2 试用

- 注册成功即写入 `member_until = now + 7 * 86400_000`，并记一条 `membership_logs(action='trial', days=7)`。
- 试用到期自动降为免费账号，数据不删除。
- 防刷：复用现有按 IP 的注册限流；同一 IP 每日注册上限建议 3 个。

### 9.3 兑换码

- 格式：`MGR-XXXX-XXXX-XXXX`，字符集去掉易混淆的 `0/O/1/I`。
- 生成：管理员在后台选时长（30/90/365 天）与数量，批量写入，`batch_id` 便于导出与作废。
- 使用：`POST /api/membership/redeem`；一码一人一次，绑定后不可再用。
- 续期：`member_until = max(now, member_until) + duration_days`。
- 作废：仅未使用的码可作废；已兑换的码通过后台调整用户会员来退款。
- 限流：同一用户每分钟最多 5 次兑换尝试，失败按 IP 计数。

### 9.4 到期行为

- 服务端：`requireMember` 拒绝同步与包下载（`builtin` 除外）。
- 客户端：已下载题库继续可读，不做二次校验；同步与下载入口提示续费。
- 云端进度保留，续费后自动恢复。

### 10.3 容器化与部署（Docker）

**沿用现有形态**：`apps/server/Dockerfile` 是单镜像，Node 进程同时提供 API 与静态产物；`apps/server/deploy/docker-compose.yml` 里 Caddy 只做 TLS 反代。新增 admin 后不引入额外的静态服务器，也不拆多镜像。

镜像内布局：

```
/app
├─ apps/server/src          # tsx 直接运行，无编译步骤
├─ data/questions.json      # 仅用于首次 seed builtin 题库
├─ apps/web/dist            # 单文件 index.html
└─ apps/admin/dist          # 普通多文件 SPA
```

**Dockerfile 改动清单**：

1. 依赖清单 COPY 增加 `apps/admin/package.json`；
2. 安装命令扩展为
   `pnpm install --frozen-lockfile --filter @megrez/server... --filter @megrez/web... --filter @megrez/admin...`；
3. 源码 COPY 增加 `apps/admin`；
4. 构建步骤改为
   `RUN pnpm --filter @megrez/web build && pnpm --filter @megrez/admin build`；
5. 继续用 `pnpm exec tsx src/index.ts` 启动，不为 server 增加 `dist` 编译产物；
6. `HEALTHCHECK` 保持 `/api/health`。

**静态托管**（`apps/server/src/index.ts`）：

| 路径 | 来源 |
| --- | --- |
| `/api/*` | 路由 |
| `/admin/*` | `apps/admin/dist`，未命中时回退 `admin/index.html` |
| 其余 | `apps/web/dist`，未命中时回退 `index.html` |

实现上再注册一个 `@fastify/static`（`prefix: '/admin/'`，`wildcard: false`），并在 `setNotFoundHandler` 里先判断 `/admin` 前缀，避免两份 SPA 的 fallback 互相抢路由。

**新增环境变量**：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `ADMIN_DIST` | `../admin/dist` | admin 静态产物目录 |
| `QUESTIONS_PATH` | `/app/data/questions.json` | 首次 seed 内置题库用，之后以数据库为准 |

**compose 改动**：`server` 服务增加 `ADMIN_DIST: /app/apps/admin/dist`；卷、端口、Caddy 配置都不变。

**构建与升级**：

```bash
# 首次/全量重建
docker compose -f apps/server/deploy/docker-compose.yml up -d --build

# 升级镜像（题库内容在数据库里，升级不会覆盖已发布内容）
docker compose -f apps/server/deploy/docker-compose.yml build server
docker compose -f apps/server/deploy/docker-compose.yml up -d
```

**启动顺序（容器内自动执行）**：

1. 建表 / `ALTER TABLE` 迁移；
2. `banks` 为空时从 `QUESTIONS_PATH` seed `builtin` 并发布 v1；
3. 旧 `user_states` 迁入 `(user_id, 'builtin')`；
4. 迁移完成后监听端口。

`seedBuiltinBank()` 必须**幂等**：只在 `banks` 表为空时执行，绝不能覆盖运营在后台修改或发布过的内容。

**备份**：只备份 `megrez-data` 卷，注意 SQLite 的 WAL 文件要一起打包：

```bash
docker run --rm -v megrez_megrez-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/megrez-$(date +%F).tgz -C /data .
```

**开发期**：`pnpm admin:dev` 用 Vite `server.proxy` 把 `/api` 代理到 `127.0.0.1:8787`；`pnpm server:dev` 同时托管 `apps/web/dist` 与 `apps/admin/dist`（未构建时只提供 API）。

## 十二、迁移方案

### 12.1 服务端

以下步骤在 **Docker 容器启动时自动执行**（见 10.3），无需手工跑迁移脚本；本地开发同样在 `pnpm server:dev` 启动时执行。

1. 启动时检测 `users` 是否缺少 `role`/`member_until`/`disabled_at`，缺则 `ALTER TABLE`。
2. 若 `users` 非空且没有任何 `role='admin'`，把 `created_at` 最早的用户设为管理员。
3. 创建 `banks` / `bank_chapters` / `bank_questions` / `bank_releases` / `redeem_codes` / `membership_logs` / `activity_daily`。
4. 若 `banks` 为空：导入仓库 `data/questions.json` 为 `id='builtin'`，题目 `id` 用 `${c}-${n}`，发布为 `version=1`。
5. 迁移 `user_states` → `user_states_v2(user_id, 'builtin')`，删除旧表。
6. 迁移 `user_achievements` → `user_achievements_v2(user_id, 'builtin', ...)`，删除旧表。

### 12.2 客户端

1. `megrez_quiz_v1` → 复制到 `megrez_quiz_v1:builtin`，旧键保留只读。
2. `megrez_quiz_sessions_v2` → 复制到 `megrez_quiz_sessions_v2:builtin`。
3. 写标记 `megrez_migrated_v7 = 1`，幂等执行。
4. 内置题库题目补 `id = `${c}-${n}``，因此所有旧键继续命中。

### 12.3 旧客户端

- 进度快照结构未变，但存储键已按题库分。
- 旧版客户端仍读 `megrez_quiz_v1`（迁移时保留的副本），因此**本地刷题不会丢**，但看不到新数据、也无法使用新同步。
- 服务端不再向旧客户端返回无 `bank_id` 的进度；旧版调用 `/api/sync` 建议返回 `426 Upgrade Required` 与升级提示（保留一个版本周期的兼容期）。

## 十五、风险与待定

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| iOS App Store 政策 | 数字内容订阅必须走 IAP，站外兑换码有被拒风险 | 只发 Android/桌面/Web；上 iOS 前补 IAP |
| `file://` 下 IndexedDB 不可用 | 双击单文件打开时部分浏览器禁用 IndexedDB | 回退 localStorage，限制 1 个非内置题库 |
| 免费用户进度不上传 | 换设备即丢，用户可能困惑 | 同步入口明确标注「会员功能」，升级后首次同步自动合并 |
| 旧客户端数据割裂 | 迁移后旧版看不到新数据 | 保留旧键只读 + 升级提示 |
| 题库包约 2–3 MB | 首次下载耗时 | gzip + 下载进度 + ETag 缓存 |
| 兑换码转卖/分享 | 一次性绑定账号可缓解 | 后续可加设备数限制 |
