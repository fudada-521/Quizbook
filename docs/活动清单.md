> 关系：`WBS.md`（交付物）→ **本文（活动、依赖、工期、责任）** → [`活动顺序.md`](活动顺序.md)（排序、关键路径、执行顺序）→ `实施任务分解.md`（工程工单、文件、验收细节）。

## 一、活动属性

每个活动定义以下属性：

| 属性 | 说明 |
| --- | --- |
| ID | `A{阶段}{序号}`，唯一且不复用 |
| WBS | 对应 `WBS.md` 的工作包编号 |
| 活动 | 可执行的动作，动词开头 |
| 前置 | 必须完成的前置活动 ID |
| 工期 | 人日，含自测；不含返工 |
| 角色 | 后端 / 客户端 / 全栈 / 测试 / 运维 / 负责人 |
| 完成判据 | 可观察的完成标准 |
| 对应工单 | `实施任务分解.md` 的 P 编号 |

约定：

- 工期按**单人有效投入**估算，不含等待、评审与沟通开销。
- 一个活动产出一个可提交的变更或一份可验证的记录。
- 同一活动内不混入不同角色的工作。

## 十四、活动清单的维护

1. 新增活动必须挂到已有 WBS 工作包；没有工作包就先改 WBS。
2. 活动 ID 不复用；取消的活动标记「已取消」，不删除。
3. 实际工期与估算偏差超过 50% 时，回头修正同类型后续活动的估算。
4. 里程碑验收通过后，冻结该阶段活动清单，变更走 `WBS.md` 第八节的变更控制。
