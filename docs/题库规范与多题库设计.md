## 一、现状：题库是怎么构建的

### 1.1 数据源与流动路径

```
data/questions.json  ——构建期——▶  apps/web/src/App.tsx  (import rawData)
                                       │ useMemo 克隆
                                       ▼
                              <QuizProvider data={data}>      apps/web/src/store/QuizStore.tsx
                                       │  data 挂在 context
                                       ▼
             HomeView / QuizView / ResultView / FavoritesView / AchievementsView
                                       │
                    gradeAnswer(state, item, pickIdx)  packages/core/src/logic.ts:81
                                       ▼
                     PersistedState.answers[`${c}-${n}`]  →  localStorage
```

要点：

| 事实 | 位置 | 影响 |
|------|------|------|
| 题库以 JSON 形式 `import`，编进 Web bundle | `apps/web/src/App.tsx:14` | 改题库必须重新 `pnpm build`；桌面/移动端要重新 sync/打包 |
| 构建产物是**单文件** `index.html`（JS/CSS 全内联） | `vite-plugin-singlefile` | 不支持运行时按需 fetch 额外文件，否则破坏「双击离线打开」 |
| 题库**没有任何 id / 版本字段** | `packages/core/src/types.ts:24-29` | 无法区分来源，无法做迁移与校验 |
| 进度靠 `qkey()` = `` `${c}-${n}` `` 定位题目 | `types.ts:180-182` | **不含题库维度**：两套题库的同号题会撞键 |
| `o` 被类型约束为**固定 4 元组** `[string,string,string,string]` | `types.ts:17` | 判断题（2 项）、多选/多空（8 项）无法表达 |
| `a` 被约束为**单个 0 基下标** `number` | `types.ts:19` | 多选/多空题无法表达 |
| 选项渲染遍历 `item.map`（长度 4 的乱序映射） | `apps/web/src/components/AnswerParts.tsx:22`、`logic.ts:37` `makeMap` | 选项数写死为 4，`LETTERS` 只有 A–D |
| 判分 `realOpt === item.q.a` | `logic.ts:87-88` | 只支持单选 |
| 每日一练对 `data.questions` 整体洗牌取前 N | `packages/core/src/challenges.ts:63` | 题库构成变了，同一天的每日一练题集就变 |
| 服务端只读仓库里的 `data/questions.json` 做成就权威校验 | `apps/server/src/questions.ts` | 服务端也要知道"哪套题库、有哪些题" |
| 会话快照只存 `${c}-${n}`，加载时按当前题库重新关联 | `apps/web/src/store/sessionPersistence.ts:120-124` | 切题库后快照会因找不到题被**整份丢弃** |

### 1.2 现有题库的实际形状（`答题程序/data/questions.json`，2210 题）

```jsonc
{
  "generatedFrom": "软考·信息系统项目管理师 综合知识题库",
  "chapters": { "1": "信息化发展", "2": "信息技术发展", ... "26": "..." },
  "questions": [
    { "c": 1, "n": 1, "s": "题干", "o": ["A项","B项","C项","D项"], "a": 3, "e": "解析" }
  ]
}
```

实测统计：全部 2210 题 `o.length === 4`、`a` 全部为 `int`。也就是说**当前类型约束与数据是一致的**，`o` 固定 4 项并非历史包袱，而是这份题库的真实约束。

### 1.3 进度数据形状

`PersistedState`（`types.ts:102-121`，`SCHEMA_VERSION = 5`）：

```ts
{
  schemaVersion: 5,
  answers:   { "1-1": { ok, tries, t } },   // 键 = `${c}-${n}`
  wrong:     { "1-1": 2 },
  favorites: { "1-1": 1717000000000 },
  favoriteRemovals: { ... },                 // 取消收藏墓碑
  notes:     { "1-1": [{ id, text, at }] },
  settings:  {...}, settingsAt,
  daily:     { "2026-11-05": { answered, correct, completed, t } },
  challenges: [{ id, kind, date, score, total, durationMs, finishedAt, passed? }],
  achievements: { "a1": { unlockedAt } },
  resetAt: 0
}
```

注意：`daily`、`challenges`、`achievements` 都是**全局**的，不带题库维度；而 `answers` / `wrong` / `favorites` / `notes` 以题目键为键。

## 二、新题库（清晖在线题库）与现有题库的差异

`清晖-高项在线题库/questions.json` 实测（2997 题）：

| 项目 | 现有题库 | 清晖题库 | 处理结论 |
|------|---------|---------|----------|
| 题量 | 2210 | 2997 | — |
| 章节 | 1–26（教材章） | 1–24 教材章 + 25 综合套卷 + 26 案例套卷 | 章节模型不同，需支持"试卷型章节" |
| `o` 长度 | 全部 4 | 4 项 2726、**2 项 216**（判断）、**8 项 52**（双空）、7 项 2、5 项 1 | ⚠️ 必须放开固定 4 项 |
| `a` 类型 | 全部 `int` | 2943 个 `int`、**54 个数组** | ⚠️ 必须支持多选答案 |
| 额外字段 | 无 | `src`（分章练习/课后练习/综合知识套卷/案例分析套卷） | 可选保留 |
| 题型 | 仅单选 | 单选 2893、判断 50、多选/双空 54 | 需标注题型 |
| 答案来源 | 教材整理 | 平台交卷后接口返回（含解析） | 需记录来源以便追溯 |

**因此"切换题库"不是换一个 JSON 文件那么简单**：清晖题库里有 216 题判断题和 54 题多选/双空，现有渲染、判分、乱序映射、会话快照、成就校验都会遇到。

## 三、题库文件规范（v2）

### 3.1 文件位置与命名

```
答题程序/data/
├── banks/
│   ├── index.json            # 题库清单（构建期读取，决定有哪些题库）
│   ├── jiangshan.json        # 现有 2210 题（由 questions.json 迁入）
│   └── qinghui-online.json   # 清晖在线题库 2997 题
└── questions.json            # 保留一段时间作为旧路径兼容，最终删除
```

- 每个题库一个文件，文件名用**题库 id**（`[a-z0-9-]+`），不要用中文。
- `index.json` 只存元数据，供 UI 与校验使用；题量等统计由构建脚本写入，**不作为事实来源**。

### 3.2 单题库文件结构

```jsonc
{
  "schema": 2,                       // 题库文件格式版本，与进度 schemaVersion 无关
  "id": "qinghui-online",            // 必填，稳定不变，用作进度分区键
  "name": "清晖在线题库",             // 必填，UI 显示名
  "subtitle": "分章练习 + 课后练习 + 历年套卷",  // 可选
  "version": "2026-11-05",           // 必填，题库内容每次变更都改
  "source": {
    "kind": "platform",              // manual | ocr | platform
    "note": "清晖在线学堂 /my/course/3184，82 课时",
    "url": "https://www.qhclass.com/my/course/3184",
    "fetchedAt": "2026-11-05"
  },
  "chapters": { "1": "信息化发展", "25": "综合知识历年套卷", "26": "案例分析历年套卷" },
  "groups": {                        // 可选：章节分组，用于首页分区展示
    "practice": { "name": "分章练习", "chapters": [1,2,3] },
    "exam":     { "name": "历年套卷", "chapters": [25,26] }
  },
  "questions": [
    {
      "c": 1,                        // 章节号，必填
      "n": 1,                        // 章内题号，必填，章内唯一
      "t": "single",                 // 题型：single | multi | judge | blanks
      "s": "题干",
      "o": ["A项", "B项"],            // 选项数组，长度 >= 2
      "a": 0,                        // 单选/判断：0 基下标 int；multi/blanks：下标数组
      "e": "解析",
      "src": "分章练习"               // 可选，来源标签
    }
  ]
}
```

### 3.3 字段规则（硬性）

| 规则 | 说明 |
|------|------|
| `id` 不可变 | 一旦发布，`id` 改名等于换了一套新题库，所有进度与收藏都会失联 |
| `c` 与 `n` 稳定 | 进度键依赖 `${c}-${n}`；**不要**为了连续而重排 `n`（现有题库就有刻意断档） |
| `n` 章内唯一 | 同一 `c` 下 `n` 不得重复，否则进度串题 |
| `a` 是 0 基下标 | 不是选项文本，不是字母 |
| `o` 长度 ≥ 2 | 且 `a` 的每个下标都必须 `< o.length` |
| 判断题 | 建议统一 `o: ["正确","错误"]`、`a: 0/1`，`t: "judge"` |
| 多选/双空 | `a` 为**升序或按 UI 语义排列**的下标数组，`t: "multi"` 或 `"blanks"`；双空题的 `o` 里建议保留 `（1）`/`（2）` 前缀（清晖题已有） |
| 纯文本 | `s`/`o`/`e` 只放纯文本或受限 Markdown（换行 `\n`、`[图片] ` 占位）；**不要**放 HTML |
| 不写 `qkey` | 键永远由 `qkey()` 现算，不在数据里冗余存储 |

### 3.4 校验（必须自动化）

构建前运行 `pnpm check:banks`，任一题库不通过则构建失败。检查项：

1. `schema`/`id`/`name`/`version` 齐备，`id` 与文件名一致，且在 `index.json` 中唯一；
2. `questions` 非空；每条 `c` 在 `chapters` 中有对应标题；
3. `n` 章内唯一；`o.length >= 2`；`a` 为合法下标（或下标数组，全部合法且不重复）；
4. `t` 与 `a` 形状一致（`multi`/`blanks` ⇒ 数组；其余 ⇒ int）；
5. 题干非空；`e` 允许为空字符串或 `"无解析"`；
6. 统计题量并与 `index.json` 记录的题量比对，不一致只**告警**（题库会更新）；
7. 跨题库检查：不同 `id` 之间不要求 `c/n` 唯一（因为键会被题库隔离），但要**不要**出现同样的 `id`。

## 四、切换题库设计

### 4.1 设计原则

1. **题库离线可用**：所有题库仍在构建期打进 bundle（保持单文件离线特性），切换是内存中换 `data`，不发起网络请求。
2. **进度按题库隔离**：切题库 = 换一套独立进度，互不污染。
3. **默认行为不破坏**：老用户升级后，原进度自动落到默认题库 (`jiangshan`)，无感。
4. **会话与题库绑定**：切换时把当前会话写入快照（带题库 id），切回来能续做。

### 4.2 进度存储分区（核心决策）

**方案 A：进度键加题库前缀**（推荐）

```
answers["qinghui-online:1-1"] = { ok, tries, t }
```

- 优点：一套 `PersistedState`，现有 `answers/wrong/favorites/notes` 结构不变，`mergeStates()` 的逐键合并逻辑**天然兼容**（不同题库的键永不冲突）；云同步、导入导出都不用改数据结构。
- 缺点：`daily`/`challenges`/`achievements` 是全局的，需要额外处理（见 4.3）。
- 废弃键清理：无题库前缀的旧键在迁移时补 `jiangshan:` 前缀。

路线：`qkey(q, bankId)` → `` bankId ? `${bankId}:${c}-${n}` : `${c}-${n}` ``。**注意**：所有调用 `qkey()` 的地方都必须能拿到当前题库 id，因此 `qkey` 的签名要变，调用点全部排查（`gradeAnswer`、`toggleFavorite`、`isFavorite`、`wrongQuestions`、`unansweredQuestions`、`favoriteQuestions`、`notesFor`、`addQuestionNote`、`sessionPersistence.encode/decode`）。

**方案 B：按题库分多份 `PersistedState`**

```
localStorage: quizbook_quiz_v1_<bankId>
```

- 优点：隔离最彻底，`daily`/`challenges`/`achievements` 也天然按题库分开。
- 缺点：账号同步要把多份快照一起传（服务端快照结构要改），「总收藏夹」跨题库查看会变复杂，成就体系会被割裂。

**结论**：采用 **A**，并用 `PersistedState.bankStats` 兜住全局统计的归属；如果后续发现成就想按题库独立，再升级到「A + 分区统计」。

### 4.3 全局数据如何归属

| 数据 | 现状 | 归属方案 |
|------|------|----------|
| `daily`（当天答题数/打卡） | 全局 | 保持全局：它就是"今天学了多少"，跨题库累计更符合直觉 |
| `challenges`（每日一练/限时/模拟考成绩） | 全局数组 | **加 `bank` 字段**；成就按 `bank` 过滤后计算，避免用 A 题库的模拟考成绩去解 B 题库的成就 |
| `achievements` | 全局 map | 加 `bank` 到解锁记录 `{ unlockedAt, bank }`；老记录视为默认题库 |
| `settings` | 全局 | 保持全局（用户偏好与题库无关） |

`mergeStates()` 需同步：`challenges` 已按 `id` 去重，把 `bank` 并入 `id` 生成规则即可；`achievements` 合并时以「谁先解锁」为准，`bank` 取先解锁那一方。

### 4.4 运行时接口改造

**`QuizData` 增加身份，`QuizBank` 作为容器**：

```ts
// packages/core/src/types.ts
export interface Question {
  c: number;
  n: number;
  t: QuestionType;           // 新增，缺省视为 'single'
  s: string;
  o: string[];               // 由 4 元组放开为数组
  a: number | number[];      // 新增数组
  e: string;
  src?: string;
}

export interface QuizBank extends QuizData {
  id: string;                // 新增，必填
  name: string;
  version: string;
  source?: { kind: string; note?: string; url?: string; fetchedAt?: string };
  groups?: Record<string, { name: string; chapters: number[] }>;
}
```

**Store 层**：`QuizProvider` 由「一份 data」改为「题库清单 + 当前题库 + 切换动作」：

```ts
interface QuizApp {
  banks: BankMeta[];              // 来自 data/banks/index.json
  bankId: string;                 // 当前题库
  data: QuizBank;                 // 当前题库（保持原字段名，减少改动面）
  switchBank(id: string): void;   // 切换
  ...
}
```

`bankId` 持久化在**独立键** `quizbook_quiz_bank_v1`（不放进 `PersistedState`，避免多端合并时互相覆盖；也可以放进 `settings`，但要单列字段）。

### 4.5 切换时的行为（必须逐条实现）

```
switchBank(next):
  1. next === current            → 无操作
  2. 当前在答题中              → 先把会话存快照（快照内写入 bankId），再清空 app.session
  3. 载入 next 题库            → data = banks[next]（内存里已有，无需异步）
  4. 重新加载该题库的未完成会话（按 bankId 过滤快照）
  5. 重新评估成就（用新题库的题量/章节范围，按 bank 隔离）
  6. 写入 quizbook_quiz_bank_v1
  7. 回到首页
```

**会话快照**：`StoredSession` 增加 `bank: string`；`loadSessions(data, bankId)` 只取出 `bank === bankId` 的快照；解码时按当前题库的题键查找。切换题库后旧题库会话**保留不删**，切回来即可续做。旧快照无 `bank` 字段时视为默认题库。

### 4.6 题型渲染与判分（前置改造）

多题库的真正难点在题型，必须先做（否则清晖题库直接渲染出错）：

| 位置 | 改动 |
|------|------|
| `makeMap` | 由固定 4 元组改为 `number[]`，长度 = `q.o.length` |
| `SessionItem.map` | 类型改为 `number[]` |
| `gradeAnswer` | 单选：`realOpt === q.a`；多选/多空：判 `pickSet` 与 `q.a` 集合相等（**部分对不计分**或按"漏选半分"另议，建议先严格） |
| `grade(pickIdx)` | 多选需要新入口 `togglePick(idx)` + `submitMulti()`，`pick` 语义变为"显示下标集合" |
| `AnswerOptions` | `LETTERS` 扩到 A–H；多选渲染 checkbox |
| `sessionPersistence` | `isMap` 的"长度 4、无重复"校验改为"长度 = 该题 `o.length`、无重复"，解码时按题重新校验 |
| 键盘快捷键 | A–D 扩到 A–H |
| 模拟考计分 | `scoreSession` 同理按题型判分 |

建议做**分阶段**：

1. **阶段 1（可先上线）**：只做"题库切换 + 进度隔离"，并要求所有题库都满足「4 选项单选」。清晖题库先只导入满足条件的 2726 题（剔除 216 判断 + 54 多选/双空），外加 `t:"single"`。
2. **阶段 2**：放开 `o`/`a` 与题型（判断题优先，因为它最简单）。
3. **阶段 3**：多选/多空（涉及判分规则与交互）。

### 4.7 UI 入口

- **设置页**新增「题库」区块：列出 `index.json` 里的题库（名称、题量、章节数、版本、来源），单选切换；切换前若在答题中，提示"当前练习会保存进度"。
- **首页**标题下方或章节列表上方，用一个轻量的下拉/胶囊显示当前题库名，点击进入题库选择（避免为了切换而进设置）。
- 品牌副标题 `综合知识` 是写死的（`App.tsx:131`），应改为当前题库的 `subtitle`。

## 五、数据迁移

1. **题库文件迁移**：`data/questions.json` → `data/banks/jiangshan.json`，补 `id/name/version/schema`，题条目不改动（`o` 4 项、`a` int 保持原样即合法）。
2. **进度迁移**（`SCHEMA_VERSION` 5 → 6）：`normalizeState()` 中，若发现键不含 `:` 分隔的题库前缀，按默认题库补前缀；`challenges`/`achievements` 补 `bank: 'jiangshan'`。**必须幂等**，重复执行不重复加前缀。
3. **会话迁移**：快照里没有 `bank` 的，按默认题库处理；`clearAllSessions()` 语义不变。
4. 老用户的 `quizbook_quiz_bank_v1` 不存在时默认 `jiangshan`。

## 七、风险与待定

| 风险 | 说明 | 建议 |
|------|------|------|
| 单文件体积 | 两套题库原始 JSON ≈ 4.5 MB（1.6 + 2.9），内联后 gzip 可能到 1.5–2 MB | 先实测；超 3 MB 再考虑「动态 import 分题库」——注意 `vite-plugin-singlefile` 配合 `inlineDynamicImports` 仍可单文件，只是加载时机变了 |
| 题库版本变化 | 题库更新后题号变化会导致进度错位 | `version` 只做提示；不对已有进度做重映射（成本高、易出错） |
| 答案正确性 | 清晖题库答案来自平台交卷接口 | 建议在题库文件里保留 `source.url`，出现争议时能回溯 |
| 多选计分规则 | 软考多选"少选得分"有惯例 | 需产品决策：严格全对 or 部分给分；先严格，再评估 |
| `qkey` 签名变更的波及面 | 调用点较多且分散 | 机械替换 + 单测覆盖（core 已有 `packages/core/test/core.test.ts`） |
