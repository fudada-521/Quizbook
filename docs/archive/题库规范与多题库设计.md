## 一、目标与已确认决策

### 1.1 要解决的问题

- 一套代码需要支持多套题库（软考高项、清晖在线题库等），且题库可独立更新。
- 用户能导入（下载）、删除、切换题库，进度互不污染。
- 保持现有「单文件 `index.html`、双击离线可用」的发行形态。

### 1.2 决策清单

| # | 决策项 | 结论 | 备注 |
|---|--------|------|------|
| 1 | 题库来源 | **内置 1 套 + 服务端题库商店下载** | 内置为现有 2210 题（id `builtin`），不可删除 |
| 2 | 本地文件导入 | **不做** | 三端都不接文件选择器 |
| 3 | 题型范围 | **单选 + 判断（2 选项）** | 多选/双空暂不支持；上传时自动剔除 |
| 4 | 删除题库 | 弹窗确认，**用户勾选是否清除该题库进度** | 默认勾选「同时清除」 |
| 5 | 题库更新 | 服务端版本更高时提示「可更新」，**手动更新** | id 不变则进度保留 |
| 6 | 管理后台 | **内置到现有 Web**，仅管理员可见 | 复用现有设计令牌，接口做服务端鉴权 |
| 7 | 挑战/成就归属 | 挑战按题库独立；**成就方案待最终确认**（推荐全局） | 见第六节 |
| 8 | 管理员分配 | **最早注册用户自动为管理员**，后台可提升他人 | 建议再加 `ADMIN_USERNAMES` 环境变量引导 |
| 9 | 每日统计 `daily` | **保持全局** | 不按题库分区，避免打卡连续天数被切碎 |
| 10 | 内置题库位置 | 仍编进 bundle | 不改单文件构建方式 |

> 待确认项只有第 7 条的成就归属。推荐方案 A（成就全局），理由见 6.2。

## 二、总体架构

```
构建期
  data/questions.json ──import──▶ App.tsx ──包装元数据──▶ 内置 QuizBank (id: builtin)
                                                              │
运行时                                                         ▼
  服务端 /api/banks ──登录下载──▶ IndexedDB (megrez_banks) ──▶ BankRepository
                                                              │
                                    ┌─────────────────────────┘
                                    ▼
                          QuizStore：banks + bankId + data
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
          HomeView 胶囊        SettingsView 题库区     BankStoreView / BankAdminView
                                    │
                                    ▼
                   PersistedState（键带 bankId 前缀）──▶ localStorage / 云同步
```

要点：

- 题库文件只在「下载/更新」时走网络；切换题库是内存换 `data`，已下载题库离线可用。
- 内置题库不落 IndexedDB，与已安装列表合并后展示。
- 进度仍是**一份** `PersistedState`，靠题目键前缀隔离。
- 服务端只存题库文件，不存用户下载状态；下载状态是设备级。

## 三、题库文件规范 v2

### 3.1 文件结构

```jsonc
{
  "schema": 2,                        // 题库文件格式版本，与进度 schemaVersion 无关
  "id": "qinghui-online",             // 必填，稳定不变，进度分区键
  "name": "清晖在线题库",              // 必填，UI 显示名
  "subtitle": "分章练习 + 历年套卷",    // 可选，首页副标题
  "version": "2026-11-05",            // 必填，内容每次变更都改
  "source": {                         // 可选，便于追溯
    "kind": "platform",               // manual | ocr | platform
    "note": "清晖在线学堂 /my/course/3184",
    "url": "https://www.qhclass.com/my/course/3184",
    "fetchedAt": "2026-11-05"
  },
  "chapters": { "1": "信息化发展", "25": "综合知识历年套卷" },
  "questions": [
    {
      "c": 1,                         // 章节号，必填
      "n": 1,                         // 章内题号，必填，章内唯一
      "t": "single",                  // single | judge，缺省为 single
      "s": "题干",
      "o": ["A项", "B项", "C项", "D项"], // 选项，长度 >= 2
      "a": 3,                         // 0 基下标，int
      "e": "解析",
      "src": "分章练习"                // 可选，来源标签
    }
  ]
}
```

### 3.2 字段规则（硬性）

| 规则 | 说明 |
|------|------|
| `id` 不可变 | 改名等于换新题库，所有进度会失联 |
| `id` 格式 | `[a-z0-9-]+`，不含冒号（进度键用 `:` 分隔） |
| `c` / `n` 稳定 | 进度键依赖 `${c}-${n}`；不要为连续而重排 `n` |
| `n` 章内唯一 | 同一 `c` 下重复会导致进度串题 |
| `o.length >= 2` | 判断题建议统一 `["正确", "错误"]`、`a: 0/1`、`t: "judge"` |
| `a` 为 int | 0 基下标，必须 `< o.length` |
| `a` 为数组 | **本期不支持**，上传时整题剔除（记入剔除数） |
| `t` 与 `a` 一致 | `single`/`judge` ⇒ int；数组答案一律剔除 |
| 纯文本 | `s`/`o`/`e` 只放纯文本或受限 Markdown；不放 HTML |
| 不写 `qkey` | 键永远由 `qkey()` 现算 |

### 3.3 校验（服务端上传时执行）

新增 `@megrez/core` 的 `validateBank(input)`，返回：

```ts
{
  bank: QuizBank;        // 规范化后的题库
  removed: number;       // 被剔除的题数（多选/双空/非法题）
  warnings: string[];    // 如题量与元数据不符、空解析
}
```

检查项：

1. `schema` / `id` / `name` / `version` 齐备，`id` 与文件名一致；
2. `questions` 非空；每条 `c` 在 `chapters` 中有标题；
3. `n` 章内唯一；`o.length >= 2`；`a` 为合法下标；
4. `t` 与 `a` 形状一致；不支持的题型剔除；
5. 题干非空；`e` 允许为空；
6. `version` 变化时题量变化只告警，不阻断；
7. 内置题库同样跑一遍校验（构建/单测期）。

## 四、客户端

### 4.1 题库仓库（IndexedDB）

新增 `packages/storage/src/banks.ts`：

```ts
export interface InstalledBankMeta {
  id: string;
  name: string;
  subtitle?: string;
  version: string;
  questionCount: number;
  chapterCount: number;
  installedAt: number;
  serverUpdatedAt: number;
}

export interface BankRepository {
  list(): Promise<InstalledBankMeta[]>;
  get(id: string): Promise<QuizBank | null>;
  put(bank: QuizBank, meta: Omit<InstalledBankMeta, 'installedAt'>): Promise<void>;
  remove(id: string): Promise<void>;
}
```

- 数据库 `megrez_banks`，对象仓库 `banks`，`keyPath: 'id'`。
- 单题库 JSON 约 3 MB，IndexedDB 足够；不使用 localStorage。
- 内置题库不进 IndexedDB，读取时由 `builtinBank()` 直接返回。
- IndexedDB 在 Tauri / Capacitor WebView 中均可用，但需真机验证持久性；接口已隔离，后续可替换为原生存储。

### 4.2 当前题库与切换

- 当前题库 id 存独立 localStorage 键 `megrez_bank_v1`，默认 `builtin`。
- 不放进 `PersistedState`，避免多端合并时互相覆盖。

```
switchBank(next):
  1. next === current            → 无操作
  2. 当前在答题中                → 先存会话快照（含 bankId），清空 app.session
  3. data = builtin / IndexedDB  → 内存切换，无需异步加载
  4. 载入该题库的未完成会话
  5. 用新题库重新评估成就（若成就全局则只刷新章节完成度）
  6. 写 megrez_bank_v1
  7. 回到首页
```

### 4.3 删除

弹窗内容：

- 题库名称、题量、版本；
- 勾选项「同时清除该题库的答题记录、错题、收藏、心得」（默认勾选）。

行为：

| 勾选 | 本地 | 云同步 |
|------|------|--------|
| 是 | 删题库文件 + 带前缀的记录 + 该题库会话；写 `bankResets[bankId] = now` | `bankResets` 随快照上传，合并时丢弃早于该纪元的记录 |
| 否 | 只删题库文件，记录保留 | 记录不动；重新下载同 id 题库可继续 |

内置题库不可删除。

### 4.4 更新

- 商店列表返回服务端 `updatedAt`；本地保存 `serverUpdatedAt`。
- 服务端 `updatedAt` 更新时显示「可更新」。
- 更新 = 重新下载覆盖题库文件；`id` 不变，进度与收藏保留。
- 题号漂移不做自动重映射，只在更新确认弹窗提示「若题库题号有调整，部分记录可能对不上」。

### 4.5 会话快照

`StoredSession` 增加 `bank: string`：

- `saveSession(session)` 写入 `bank`；
- `loadSessions(data, bankId)` 只返回 `bank === bankId` 的快照；
- `StoredItem.k` 仍存 `${c}-${n}`（不带前缀），加载时按当前题库关联；
- 旧快照无 `bank` 时视为 `builtin`；
- 切换题库不删除其他题库的快照，切回来可续做。

## 五、进度模型

### 5.1 题目键加题库前缀

`packages/core/src/types.ts`：

```ts
export const BUILTIN_BANK_ID = 'builtin';

export function qkey(q: Pick<Question, 'c' | 'n'>, bankId: string = BUILTIN_BANK_ID): string {
  return `${bankId}:${q.c}-${q.n}`;
}
```

- 所有键统一带前缀，包括内置题库，避免「有无前缀」两套判断。
- 迁移时无前缀旧键补 `builtin:`。
- 所有 `qkey()` 调用点必须传入当前 `bankId`：`gradeAnswer`、`toggleFavorite`、`isFavorite`、`wrongQuestions`、`unansweredQuestions`、`favoriteQuestions`、`notesFor`、`addQuestionNote`、`achievementStats`、`sessionPersistence`。

### 5.2 `PersistedState` 变更（schemaVersion 5 → 6）

| 字段 | 变更 |
|------|------|
| `answers` / `wrong` / `favorites` / `favoriteRemovals` / `notes` | 键改为 `bankId:c-n` |
| `challenges` | 增加 `bank: string` |
| `achievements` | 若采用方案 B：键改为 `bankId:achievementId`；方案 A 则不变 |
| `daily` | **不变**（全局） |
| `bankResets` | 新增 `Record<bankId, timestamp>`，删除题库并清进度时写入 |

### 5.3 迁移（`normalizeState`）

1. 识别无 `:` 的键，补 `builtin:` 前缀；
2. 老 `challenges` 补 `bank: 'builtin'`；
3. 老 `achievements`：方案 A 不动；方案 B 补 `builtin:`；
4. `bankResets` 缺省 `{}`；
5. **幂等**：重复执行不重复加前缀、不覆盖已有 `bank`。

### 5.4 合并（`mergeStates`）

- 带前缀的键天然不冲突，`answers/wrong/favorites/notes` 的逐键合并逻辑不变。
- `challenges` 仍按 `id` 去重，`bank` 随记录保留。
- `achievements` 合并以「先解锁」为准。
- 新增 `bankResets` 合并：取每个题库的最大纪元；纪元早于它的该题库记录丢弃。
- `resetAt`（全局清空）语义不变。

### 5.5 旧客户端兼容（必须明确）

v6 快照对旧客户端不兼容：旧版 `qkey()` 返回 `1-1`，读不到 `builtin:1-1`，界面会显示进度清零。

两种策略，实施前二选一：

- **A（推荐）**：服务端按请求头 `X-Quiz-Schema` 判断，旧客户端拉取时把 `builtin:` 前缀还原为无前缀（返回 v5 形状）；
- **B**：加最低客户端版本门槛，旧版只能查看不能同步，并提示升级。

无论哪种，服务端都要保留旧版 `normalizeState` 的兼容入口。

## 六、挑战、成就与每日统计的归属

### 6.1 结论

| 数据 | 归属 | 说明 |
|------|------|------|
| `answers` / `wrong` / `favorites` / `notes` | 按题库 | 键前缀隔离 |
| 练习会话 | 按题库 | 快照带 `bank` |
| `challenges`（每日一练/限时/模拟考） | 按题库 | 记录加 `bank`，成就/统计按 bank 过滤 |
| `daily`（当天答题数、打卡） | **全局** | 「今天学了多少」跨题库累计更符合直觉 |
| `achievements` | **待定**：A 全局 / B 按题库 | 推荐 A，见 6.2 |
| `settings` | 全局 | 用户偏好与题库无关 |

### 6.2 成就归属的取舍

`achievementStats(state, data)` 当前把全量 `answers` / `daily` / `challenges` 混算，且大量成就是**绝对阈值**（答对 1000 题、答题 2000 次）。

- **方案 A（推荐）**：成就保持全局。只把 `achievementStats` 的 `byChapter` 计算改为「当前题库」，避免章节完成度串题库。改动小，符合「成就代表个人水平」的直觉。
- **方案 B**：按题库独立。需要统计函数逐项按前缀过滤，并把绝对阈值改为按题库题量缩放（如「答对题库 45%」），否则小题库永远解锁不了。工作量与回归成本明显更高。

> 定稿默认按 **A** 实施；若最终选 B，需单开一节重写 50 个成就的判定规则。

### 6.3 每日一练完成

`daily.completed` 改由 `challenges` 推导（`kind === 'daily' && bank === 当前题库 && date === 今天`），不再写入 `daily`。`daily` 只保留 `answered` / `correct` / `t`。

## 七、服务端

### 7.1 表结构

```sql
ALTER TABLE users ADD COLUMN is_admin INTEGER NOT NULL DEFAULT 0;
-- 迁移：若用户表非空，把 created_at 最早的用户设为管理员

CREATE TABLE IF NOT EXISTS banks (
  id             TEXT PRIMARY KEY,
  name           TEXT NOT NULL,
  subtitle       TEXT,
  version        TEXT NOT NULL,
  schema         INTEGER NOT NULL,
  chapters       TEXT NOT NULL,   -- JSON
  questions      TEXT NOT NULL,   -- JSON
  question_count INTEGER NOT NULL,
  chapter_count  INTEGER NOT NULL,
  source         TEXT,            -- JSON
  published      INTEGER NOT NULL DEFAULT 1,
  uploaded_by    TEXT REFERENCES users(id) ON DELETE SET NULL,
  created_at     INTEGER NOT NULL,
  updated_at     INTEGER NOT NULL
);
```

- 启动时按现有风格用 `PRAGMA table_info` 判断后迁移，不引入迁移框架。
- 题库文件与用户进度分表存储，互不影响。

### 7.2 API

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/banks` | 公开 | 商店列表（元数据，不含题目） |
| GET | `/api/banks/:id/file` | 登录 | 下载完整题库 JSON（gzip） |
| POST | `/api/admin/banks` | 管理员 | 上传/覆盖题库，JSON body，`bodyLimit: 20MB` |
| PUT | `/api/admin/banks/:id` | 管理员 | 修改上下架状态 |
| DELETE | `/api/admin/banks/:id` | 管理员 | 删除题库（已下载用户保留本地副本） |
| GET | `/api/admin/banks` | 管理员 | 含未上架题库的完整列表 |
| GET | `/api/admin/users` | 管理员 | 用户列表 |
| POST | `/api/admin/users/:id/admin` | 管理员 | 提升/取消管理员 |

上传流程：

1. 解析 JSON → `validateBank()`；
2. 有 `id` 冲突则覆盖，`version` 自动升为请求里的值或当日日期；
3. 写入 `banks`，返回 `{ id, questionCount, removed, warnings }`；
4. 管理页展示「已剔除 N 道多选/双空题」。

### 7.3 成就权威校验

`/api/sync` 与 `/api/achievements` 目前只读仓库里的 `data/questions.json`。改造：

- 从 `state` 的键前缀分组出 bankId；
- `builtin` 用内置题库，其余查 `banks` 表；
- 方案 A：每个题库分别算章节完成度，成就解锁仍全局；
- 方案 B：每个题库分别算全部成就；
- 题库查不到时跳过该题库，不影响同步。

## 十二、风险与待定

| 风险 | 说明 | 建议 |
|------|------|------|
| 成就归属待定 | 方案 B 需要重做 50 个成就阈值 | 先按 A 实施，B 单独立项 |
