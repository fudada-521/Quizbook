> 下一过程（制定进度计划）见本文第六、七节。

---

## 一、排序规则

1. **只用完成到开始（FS）关系**，不引入 SS / FF / SF，避免依赖类型过多导致排期不可读。
2. **前置只有两类**：
   - 产物依赖：后一个活动要用到前一个活动的代码或接口；
   - 数据依赖：后一个活动要用到前一个活动产生的数据（如迁移后的表）。
3. **里程碑是汇总活动**，只有紧前、没有紧后，不占用工期（本文按 0.2 人日计入验收动作）。
4. **资源约束**：默认同一角色不能并行；单人执行时全部活动串行（见 6.1）。
5. **外部依赖**：无。所有活动都在本仓库内完成。

### 4.2 如何理解「8.4 天」

8.4 天是**资源无限**时的网络工期，代表技术上的最短路径，不是实际日历工期。

- 实际单人执行受「同一角色串行」约束，总工期 = 总人日 **34.4 天**（约 7 周）。
- 双人并行时，日历工期取决于两条主轨道中较长的一条（见 6.2）。
- 排期评审时看的是**关键路径上的活动不能延后**，而不是 8.4 这个数字。

### 4.3 关键路径的稳定性

- 只要 `A208 → A404 → A412 → A413 → A414` 这条「题库目录 → 商店 → 下载 → 更新」链路不变，关键路径就不会移到服务端内部。
- 若把 A209（bundle 接口）提前到 A208 之前完成，A413 会少等 0.3 天，但关键路径不变。
- 若客户端先做 A408 再做 A404，A412 仍等 A404，关键路径不变。
