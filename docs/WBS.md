## 一、范围基线

### 1.1 包含

| 范围项 | 说明 |
| --- | --- |
| 内置题库保留 | 免费、离线、未登录可用，行为与现在一致 |
| 多题库 | 服务端发布、客户端下载/更新/切换/删除 |
| 按题库隔离的进度 | 进度、错题、收藏、心得、挑战、成就、打卡全部独立 |
| 账号体系 | 注册、登录、登出、禁用 |
| 订阅会员 | 7 天试用、兑换码开通、到期降级 |
| 多端同步 | 按题库同步，离线优先，服务端合并 |
| 管理后台 | 题库编辑、批量导入、草稿/发布、兑换码、用户、统计 |
| 容器化部署 | 单镜像 + Caddy，Web/Admin/API 同域 |
| 数据迁移 | 旧进度归入 `builtin`，旧客户端可读 |

### 1.2 不包含（本期明确不做）

| 排除项 | 原因 |
| --- | --- |
| iOS App Store 内购 | 需要单独的产品与合规设计 |
| 微信 / 支付宝在线支付 | 资质与商户号，后续替换兑换码 |
| 多选题、双空题、判断题题型实现 | 格式已预留，单独立项 |
| 本地题库文件手动导入 | 三端不接文件选择器 |
| 题库加密 / DRM | 与离线优先冲突，收益低 |
| 设备并发数限制 | 兑换码一次性绑定已够用 |
| 题库审核流 / 多级角色 | 单一 admin 角色足够 |

## 八、变更控制

1. 新增范围必须先更新本文「1.1 包含」与 WBS 字典，再进入任务分解。
2. 任何影响关键路径的变更，需要重新评估 M2 交付日期。
3. 以下情况必须开变更评审：
   - 引入在线支付或 App Store 内购；
   - 题型扩展（多选题/判断题）；
   - 进度模型从「按题库独立」改为「跨题库汇总」；
   - 管理后台合并回 Web 应用。
4. 本期「不包含」清单中的项目，未经评审不得插入迭代。
