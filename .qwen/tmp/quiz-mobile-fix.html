手机答题页：长题压进一屏，标题不再被穿字

根因不是「文字太长」本身，而是吸顶标题栏刻意保持透明（要让背景水波纹透出来）——只要整页能滚，题卡文字就会从标题底下穿过来叠在一起。改动把滚动收进标题下方，并压缩纵向留白。

实测（2210 题全量，390×844 iPhone 12 Pro 排版）

指标改动前改动后
题干+选项一屏装下77.3%（501 题需下滑）95.4%（102 题需下滑）
题卡高度 p50 / p95 / max555 / 738 / 991 px476 / 625 / 856 px
一屏可用高度619 px625 px（底部预留从 96 收到 78）
滚到深处时，标题行位置的命中元素含 question-card（题卡文字与标题同层）只有 quiz-bar 一层
整页可滚是（bug 的来源）否，滚动收进 .quiz-workspace

验证方式：headless Chrome 渲染真实 styles.css 与真实题库逐题量高；另在 pnpm build 产物上注入脚本点进答题页做端到端检查（quiz-bar=relative、ws.overflow-y=auto、window.scrollY 恒为 0、点「下一题」后 ws.scrollTop=0）。

改动内容

  • 一屏锁定 styles.css（仅 max-width:720px）：.app-shell[data-view=quiz] 高度锁 100dvh + overflow:hidden，.quiz-workspace 成为唯一滚动区并 overscroll-behavior:contain；标题栏由 sticky 改为文档流内的 relative，背景仍透明、光照常透出。
  • 压缩留白（字号不动，仍题干 17.5 / 选项 16）：卡片内边距 22→16、题号行下边距 16→8、题干行高 1.78→1.65 与下边距 20→14、选项内边距 14→11 行高 1.7→1.6、选项间距 12→9。
  • 答题卡悬浮：一屏高度锁死后它再占文档流会把题目挤成半屏（实测可用高度只剩 326px），改为悬浮在题目区之上、题号区内部滚动。
  • 切题回题首 QuizView.tsx：手机端把滚动容器 scrollTop 归零（宽屏仍连同整页回顶），避免新题停在上题的阅读位置。

未改动：≥721px 的平板/窄窗口仍是旧的透明吸顶方案（本次只按你说的范围处理手机）；如需一并覆盖，把这几条规则的媒体查询放宽到 max-width:1099px 即可。
